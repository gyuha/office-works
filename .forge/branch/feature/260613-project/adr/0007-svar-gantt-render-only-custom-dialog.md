# 간트 차트를 SVAR React Gantt로 교체하되 렌더·드래그만 쓰고 편집은 커스텀 다이얼로그 유지

## Status
accepted

## 결정
프로젝트 일정 탭의 간트 차트를 `frappe-gantt`에서 **`@svar-ui/react-gantt`(SVAR, MIT)** 로 교체한다. 단, SVAR의 기능을 전부 채택하지 않고 **렌더링 + 막대 드래그/리사이즈/진척 편집만** 사용하고, 나머지는 기존 동작을 보존한다.

- **SVAR이 담당**: 타임라인 렌더, 막대 드래그(일정 이동)·리사이즈(기간)·진척 편집. 변경은 `api.on('update-task'|'drag-task'|…)`로 받아 우리 React `tasks` state·`dirty`에 반영.
- **SVAR이 담당하지 않음(끈다)**: 내장 에디터 폼(`Editor`)과 좌측 작업 그리드(표). 막대 더블클릭은 `api.intercept`로 가로채 **기존 `TaskEditDialog`**(작업명·**부서**·기간·진척)를 연다.
- **부서색 5종**(기획/개발/디자인/QA/운영)은 SVAR 기본에 없으므로 `taskTemplate` 또는 task별 CSS 클래스(`--wx-gantt-task-*` 변수)로 **직접 재현**한다.
- **시각 스타일**은 SVAR Willow 밝은 테마 기본값을 그대로 쓰고 부서색만 입힌다(frappe 모양 픽셀 재현 안 함).
- **백엔드 스케줄 버전 API 계약은 불변** — 저장 시 SVAR state를 `Task[]`로 역매핑해 기존 `{note, tasks}` 그대로 전송.

## 맥락 / 왜
사용자가 SVAR React Gantt 사용을 명시 지정했다. 그런데 현재 데이터 모델의 핵심인 `dept`(부서) 필드와 그에 따른 5색 막대는 SVAR 기본 기능에 없다. SVAR 내장 에디터를 그대로 쓰면 부서 선택 필드가 사라지고, 부서색도 자동으로 칠해지지 않는다. 즉 "라이브러리를 통째로 채택"하면 현재 UX(부서 분류·커스텀 편집 다이얼로그)가 후퇴한다. 따라서 SVAR을 **렌더+상호작용 엔진**으로만 쓰고 도메인 특화 편집(부서)은 우리 코드가 유지하는 분업이 필요하다. SVAR 공식 데모에 "Custom edit dialog"가 있어 이 패턴(`Editor` readonly/미마운트 + `api.intercept`로 더블클릭 가로채기)은 지원된다.

## 고려한 대안
- **SVAR 네이티브 풀 채택** — 내장 인라인 편집·에디터·좌측 그리드를 그대로 사용. 코드는 가장 단순하나 부서 개념/5색을 포기하거나 단색으로 후퇴. 현재 UX 손실로 기각.
- **하이브리드(인라인 편집 + 부서색만 유지)** — SVAR 인라인 편집을 쓰되 부서색만 커스텀. 하지만 SVAR 에디터엔 부서 선택 필드가 없어 "부서 변경"을 어디서 하는지 모호해짐. 기각.
- **frappe-gantt 유지** — 교체 안 함. 사용자 지정에 반하므로 기각.

## 결과
- 간트 영역에 **렌더(SVAR)와 편집 UI(우리 다이얼로그)의 분업**이 생긴다. 미래 독자가 "왜 풀 간트 라이브러리를 넣고 자체 에디터·그리드를 껐나?" 의문을 가질 수 있다 — 답은 부서 도메인 필드 보존이다.
- `frappe-gantt` 의존성과 로컬 타입 선언(`web/src/types/frappe-gantt.d.ts`)은 제거한다.
- 부서색은 SVAR 버전업 시 `--wx-gantt-task-*` 변수/`taskTemplate` API 변경에 영향받을 수 있는 커스텀 지점이다.
- e2e 자동 검증은 Teams SSO 리다이렉트로 막혀 있어, 이 화면은 **수동 로그인 육안 검증**에 의존한다(드래그·편집·히스토리·색상·뷰모드 체크리스트).
