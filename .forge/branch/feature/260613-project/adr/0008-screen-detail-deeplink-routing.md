# 화면 내부 드릴다운(상세·탭)을 TanStack 경로 라우트로 딥링크 가능하게 매핑

## Status
accepted

## 결정
지금까지 React 내부 state로만 전환하던 화면별 드릴다운(목록→상세, 상세의 탭)을 **TanStack Router 경로 라우트로 매핑**해 URL로 직접 진입(딥링크)할 수 있게 한다. 컨벤션을 다음으로 고정한다:

- **목록 URL은 기존 그대로 유지** — `/app/{screenId}`(예 `/app/proj-list`, `/app/members-list`, `/app/team-list`, `/app/appr-sent`). nav.ts·사이드바·레지스트리 키 변경 없음.
- **상세는 base 세그먼트를 신설** — `/app/{base}/[id]` (예 `/app/proj/[id]`, `/app/members/[id]`, `/app/appr-sent/[docId]`, `/app/team-list/[nodeId]`). `/app/{base}/[id]`는 2세그먼트라 기존 단일 세그먼트 `app.$screenId.tsx`에 안 걸리므로 신규 라우트 파일을 추가한다.
- **탭이 있는 상세는 탭을 경로 세그먼트로** — `/app/{base}/[id]/[tab]`. 상세 라우트는 **레이아웃 라우트**(프로젝트를 id로 fetch + 편집용 공유 draft 보관 + 탭바 + `<Outlet/>`)이고, 각 탭은 그 자식 라우트다. 이래야 탭을 URL로 전환해도 부모 레이아웃이 마운트 유지되어 미저장 draft가 보존된다.
- **상세 데이터는 id-fetch** — 목록 쿼리에서 찾지 않고 route param `id`로 get-by-id 엔드포인트(`GET /projects/{id}`, `GET /users/{id}` 등 — 이미 존재)를 호출해 새로고침·직접 진입에도 동작.
- **편집·생성 모드는 라우팅하지 않는다** — 전체 편집(EditView)·생성(다이얼로그)·작성(write)은 transient 모드라 기존 내부 state/모달 유지. `[tab]` 세그먼트와 `edit` 충돌도 피함.
- **사이드바 활성표시 매핑** — 상세 경로(`/app/proj/[id]/…`)에서도 사이드바가 해당 목록 메뉴(`proj-list`)를 활성표시하도록 `pathToScreen`(nav.ts)이 상세 base를 목록 screenId로 매핑한다.

## 맥락 / 왜
오피스 앱은 화면 단위로는 이미 `/app/$screenId` 단일 동적 라우트로 라우팅되지만, 화면 *내부* 드릴다운(특정 프로젝트·탭·문서)은 전부 React state라 URL이 없다 → 북마크·새로고침·딥링크·뒤로가기가 불가능하다. 사용자가 `/app/proj/[id]` 형태로 하위 메뉴까지 직접 진입 가능하게, 그리고 드릴다운 있는 모든 화면(프로젝트/구성원/결재/팀)에 적용하기를 요청했다.

## 고려한 대안
- **탭을 쿼리 파라미터로**(`/app/proj/[id]?tab=gantt`) — 라우트 파일이 화면당 1개로 단순하고 탭 없는 화면과 형태가 통일된다. 그러나 사용자가 경로 세그먼트 방식을 명시 선택(`/app/proj/[id]/[tab]`)했다. 기각.
- **상세만 라우팅, 탭은 state 유지** — 구현 최소지만 "탭을 바로 들어가도록" 요구를 부분만 충족. 기각.
- **목록 URL을 `/app/proj`로 리네이밍 + `/app/proj/[id]`** — 계층이 깔끔하나 전 화면의 nav id·레지스트리·사이드바를 바꿔 회귀 면적이 큼. 동작하는 목록 라우트를 건드리지 않기로 하고 기각(목록 `proj-list` vs 상세 `proj` 네이밍 불일치는 표면적 비용으로 수용).
- **편집/생성도 라우팅**(`/app/proj/[id]/edit`, `/app/proj/new`) — transient 모드라 URL 가치가 낮고 `[tab]`과 세그먼트 충돌. 기각.

## 결과
- 목록 `proj-list` vs 상세 base `proj`의 **네이밍 불일치**가 남는다. 미래 독자가 의아할 수 있으나, 동작하는 목록 라우트 보존을 위한 의도된 선택이다.
- 상세가 **레이아웃 라우트 + Outlet 탭** 구조라, 공유 draft(탭들이 메모리 변이 후 한 번에 PUT)를 레이아웃이 들고 자식 탭에 내려준다. 탭 전환=라우트 네비게이션이지만 draft는 유지된다.
- 화면마다 드릴다운 형태가 달라(프로젝트=목록→상세+탭, 구성원=목록→상세, 결재=목록→문서, 팀=트리 노드 선택) **화면별 part-plan으로 분할**해 적용한다(`detail-deeplink-routing-1of4`~`4of4`). Part 1(프로젝트)이 공통 헬퍼/패턴을 확립하고 2~4가 재사용한다.
- 팀은 목록→상세가 아닌 **트리 노드 선택**이라 같은 경로 컨벤션을 적용하되 형태 예외다(노드 id를 URL에).
- 딥링크 시 잘못된 id는 get-by-id 404 → 상세 라우트가 not-found/목록 리다이렉트를 처리해야 한다.
